# 和平精英玩家道具集市

## Register

product

## Users

面向在手机上出售或求购和平精英地铁逃生装备、活动道具和日常道具的玩家，以及在电脑上审核店铺与商品、处理纠纷的平台运营人员。玩家以自己的店铺进行交易，不出售游戏账号，不使用打手抢单或代练进度。

## Product Purpose

沿用现有 uni-app、若依 Java 服务和 Vue 3 管理端，保留参考图的明黄市场风格，按玩家道具交易重做业务。分类为密钥、传世武器、头盔、护甲、背包、枪械、活动道具、日常道具。发布求购只需真实实名认证；出售须真实实名认证、店铺审核与已验证手机号。旧打手认证不能替代。数据由服务端持久化；订单金额、权限、库存与状态由服务端校验。

新发布采用单价 × 数量，买家选择购买件数；待付款预订库存，取消后释放，付款后计入售出数量。旧发布与旧订单保留整批计价，编辑旧发布时须重新填写单价并重新审核。求购先联系发布者，协商后从卖家的出售商品下单。道具订单使用交付凭证和买家确认收货，不使用段位或百分比进度；历史代练订单保留原语义。

新交易订单编号由服务端统一生成：`G + 北京时间 yyyyMMdd + 四位当日流水号`，如 `G202610100001`。每日从 `0001` 递增至 `9999`；达到容量时明确拒绝创建，不回绕、不截断。编号与订单同一事务保存，多实例共享数据库序号，重复下单请求返回原编号；取消订单不复用编号，历史订单编号不改写。买家、卖家、后台及售后引用同一持久化编号。

真实支付按用户要求暂不接入，测试环境的资金替身不能视为真实交易完成。真实实名渠道及小程序 SDK 联调仍需有效渠道配置。会员支持后台手动授予、取消和到期，成长支持后台带原因增减及累计等级阈值配置；所有操作记录审计，重复提交不重复生效。付费购买、自动成长奖励与会员额外权益尚未开放；会员不替代发布所需认证。

首页采用无叠加文字的大图，点击整个图片进入配置的站内页面。公开玩家主页展示昵称、自主上传的头像、个人简介、省级 IP 属地、分别判断的实名和店铺标记、会员状态和等级基础资料，并可切换公开出售及求购。求购发布人和商品发布人均有个人主页入口；未审核内容及实名材料不公开。IP 属地由服务器离线查询，未知时显示未知，客户端不能自行填写或伪造；现有访问与安全日志遵循原来的日志策略。

## Brand Personality

亲切、清晰、有活力。参考用户提供的闲鱼界面和已确认的三张设计画布，使用中文的直接表达。

## Anti-references

避免游戏门户式的暗色霓虹、纯静态按钮、用假消息或假到账冒充真实交易。业务页沿用已确认的明黄市场风格。

## Design Principles

- 页面围绕下一步操作组织信息。
- 买家、卖家和平台各自只能执行权限内的操作；店铺资料和交付凭证按所属人及审核角色限制读取。
- 发布和交易的结果跨页面一致，刷新后保留。
- 支付关闭时不能制造付款、交付或结算成功；隔离测试的模拟支付必须明确标记。
- 原生小程序和 H5 共用组件、数据接口与中文文案。

## Accessibility & Inclusion

默认保障正文对比、明确表单标签、至少 44px 操作区域、错误反馈、减少动效偏好支持。状态同时使用文字而非仅颜色表示。


## 免费积分、活动与兑换（2026-10-08）

- 积分余额独立于成长值/会员/钱包，当前只允许后台带原因免费发放；没有积分充值、付费获取、转让、提现或消费金额自动换积分接口。
- 后台积分与活动：商品类型固定为活动勋章或实物；真实公开图片上传；上下架、积分成本、库存，库存变更采用冲突检查。
- 独立小程序路径：`/pages/rewards/activity?id=活动ID`，`/pages/rewards/mall`。首页活动封面只显示图片，整图点击进入活动。
- 代码默认 `boost.free-points-draw-enabled=false`。按用户要求，2026-10-08 的既有测试站显式开启仅免费积分的抽奖；没有发放积分、创建奖品或接入充值。正式运营需由运营人员配置真实活动内容。单抽/五连由服务端安全随机决定，五连按单次价格乘 5；售罄、下架、已有勋章退出当前奖池，页面显示当前概率，逐次保存完整概率快照。
- 勋章每用户同代码一枚，领取立即显示公开个人主页；实物订单：待填写地址→待发货→已发货→本人确认完成，收货信息只向本人/有履约权限的后台开放。
- 后台权限分为 `boost:rewards:read/manage/grant/fulfill`，菜单迁移不会自动授权角色。活动封面属于公开素材，不能上传证件。
- 统一验收入口 `scripts/验收玩家交易.ps1` 包含新增 Java/MySQL、5组奖励 SFC 替身回归和实际构建 H5/admin HTTP 闭环；外部/真机未完成时退出 2，不作为发布通过。

会员成长：测试站初始等级累计阈值为 0、100、300、1000。管理员可在「玩家管理 → 查看/处理 → 会员与成长」修改；会员由后台手动授予或取消，成长必须带原因调整，不会因浏览、下单或支付自动增加。

本轮确认：发布区服为 IOS-QQ、IOS-微信、安卓QQ、安卓微信、全平台。道具介绍与详情图片替代新发布的交付约定、求购说明；图片保存到订单快照。后台内容管理可调整首页和个人页文案、大图及图片点击目标。图文活动独立页面按发布时间倒序，已结束活动保留在历史列表，可关联现有积分转盘；草稿、下架活动不公开。

## 认证、编号与成长明细（2026-10-09）

实名认证与店铺认证各有独立入口。店铺材料首次提交后锁定，拒绝也不能用户重传；后台可更正名称、介绍、证明图片及短信核验后的手机号，校验资料版本，保留历次私密材料并重新审核。更正时下架现有出售商品，求购不受店铺状态影响。旧版店铺若无已验证手机号，须由后台补验，不自动认定验证通过。

手机号暂用于店铺认证，注册必填方案待用户确认。短信接入预留腾讯云单变量验证码模板，未配置时关闭发送并明确显示。实名渠道和微信 SDK 尚未完成外部验收；不能以电话验证或人工店铺审核冒充实名。公开用户编号为从 10001 起顺延、固定1开头的五位纯数字（最大19999），由内部用户ID加10000稳定生成；旧KK编号只保留查询兼容，展示统一为新编号。容量耗尽时拒绝新注册并回滚，不截断、不复用编号。可在个人页查看及精确查找玩家；号码、证件和店铺材料不公开。成长卡片点击进入等级、会员有效期、门槛及本人真实成长流水，规则仍为后台手动调整。

## 钱包保证金展示（2026-10-11）

用户确认本轮只展示保证金金额与说明，暂不开放缴纳、退还或后台管理。保证金以独立的 `deposit_cents` 字段保存，默认 0，只通过本人钱包接口读取，不计入可提现余额、累计收入和待结算。页面不提供缴退按钮；旧服务端缺少该字段时显示“暂未获取”，不能当作零金额。支付继续关闭，发布认证规则不变。启用真实缴退前须另行明确规则并实现完整资金流水与审计。
